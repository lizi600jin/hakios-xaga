## 二、每条方案发出前，主控必须给齐五样

过去的交接只给"补丁形态 + 判据"，不够。从现在起每份交接必须包含：

| # | 内容 | 为什么 |
|---|---|---|
| 1 | **我的假设**（一句话，可证伪） | 让执行者能直接攻击假设，而不是攻击补丁 |
| 2 | **支持证据**（文件:行号 / 日志行 / 外部基线） | 否则它无法判断我是不是又搞错了 |
| 3 | **反证条件**（什么观测会推翻它） | 双向可证伪 |
| 4 | **我漏考虑的可能性**（我自己列 2-3 条） | 主动暴露盲区，邀请补刀 |
| 5 | **替代方案**（如果这条失败，下一条是什么） | 避免一轮跑完就卡住 |

## 五、这一轮（MFG0 probe）作为第一个按新规程的例子

我刚发的 `HANDOFF-TO-CODEX-2026-11-13-1815.md` 是按旧格式写的。补一份元信息：

### 我的假设

> **MFG0（`0xEB8`）在健康机上一直开着（`0xC000224D`），而我们从来没碰过它。
> 如果它在我们这里是关的，GPU 的 AXI 主控域就没有 master 身份，下游访问会被静默丢弃 ——
> 这能解释「`debug_top` 卡 `0x1b` + MCU 零执行 + 无 fault」这个组合。**

### 支持证据

- `grep -n "0x0eb8\|MFG0" hakios.mali610.c` → **零命中**（驱动从未引用）
- `grep "0xeb8\|MFG0" trial-689-mali.txt` → **零命中**（日志从未出现）
- 健康机基线：`/tmp/xaga-r54/docs/GPUEB.zh-CN.md:460-530`（三次快照全一致）
- 偏移在 `gSpm` 4KB 窗口内（`0x1C001000 + 0xEB8 = 0x1C001EB8`），不在禁读列表

### 反证条件（什么会推翻它）

1. **读到 `0xC000224D`** → MFG0 是开的，假设直接作废
2. 读到关，但读的时机不对（我们没在渲染，健康机是在渲染时读的）→ **弱证据，不能判死**
3. `skipprot` 那条先跑成功 → 说明根因在别处，MFG0 只是巧合

### 我漏考虑的可能性（请补刀）

1. **`MFG0` 可能不由 SPM 控制**（它是常驻域，由 bootloader 直接开），
   那我们读到 `0xC000224D` 是"正常"，读到关是"bootloader 没做"，两种情况处理不同
2. **读 `0xEB8` 可能挂总线**（如果 MFG0 真的没电，读它自己的控制字可能不返回）
   —— 概率低（`0xEBC` 我们读了几百次没问题），但值得执行者判断
3. **健康机的 `0xC000224D` 可能是 Linux scpsys 写的，不是 bootloader** ——
   如果那样，裸机 XNU 就不可能复现这个状态

### 替代方案

如果 MFG0 是开的 → `mali_skipprot=1`（更正版，不用 `continue`）→ 段加载顺序 → 换固件
