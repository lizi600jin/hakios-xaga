# 更正：我说 713「`signature_size = 0`，无签名」是错的

> 2026-11-17 01:32，DSH。**原文保留，此处追加更正。**

---

## 我原来写的（错误）

**在 `README.md` 与 `CMD-COMPLIANCE.md` 里我写过：**

> ~~「`signature_size = 0`，此 boot 镜像无 v4 签名段，**无签名可破坏**」~~
>
> ~~「**保留 signature size 与 signature** | ✅ **`signature_size = 0`，此镜像无 v4 签名段**，无签名可破坏」~~

---

## 错在哪

**`boot_img_hdr_v4` 的字段布局：**

```
offset 0     magic
offset 8     kernel_size
offset 12    ramdisk_size
offset 20    header_size    = 1584
offset 44    cmdline[1536]  → 44..1580
offset 1580  signature_size ← 在这
header 结束  1584
```

**`signature_size` 在 **`1580`**，不是 `1584`。**

**`1584` 已经是 header 之外，读到的那个 `0` 是 **padding**。**

**我实际验证（三方一致）：**

| 镜像 | `header_size` | **`word@1580`** | `word@1584` |
|---|---|---|---|
| stock | 1584 | **4096** | 0 |
| 713 | 1584 | **4096** | 0 |
| 714 | 1584 | **4096** | 0 |

**→ 正确值是 `4096`，不是 `0`。**

---

## 正确的事实

**stock、713、714 三方都声明 4096 字节签名，且签名体逐字节相同：**

| 镜像 | 签名 offset | magic | SHA256 |
|---|---|---|---|
| **stock** | **17190912** | **`AVB0`** | **`692c87adcc6ad5fcf0592878a6fe56f13e0da9dfade792f1e8aa1f03e34623c5`** |
| **713** | **22990848** | **`AVB0`** | **同上** |
| **714** | **22990848** | **`AVB0`** | **同上** |

**签名 offset 的算法（`chainboot.py` 第 10-11 行）：**

```
offset = 4096 + paged(kernel_size) + paged(ramdisk_size)
```

**三方签名**逐字节相同**。**

---

## 为什么这不改变「签名被保留」这个结论

**结论本身是对的，只是我给的理由错了。**

| 项 | 我原来的说法 | 正确 |
|---|---|---|
| 签名是否保留 | ✅ 是 | ✅ 是 |
| **理由** | ~~「没有签名段」~~ | **「有 4096 字节签名，且逐字节复制」** |

**结构的验证器（`chainboot.py` 与 Codex 的独立复核）一直按 `1580` 读并比较这 4096 字节 —— 它们是对的，是我文档写错了。**

---

## 一个必须说清的边界

**签名逐字节保留 ≠ 密码学验证通过。**

**`chainboot.py` 第 21 行原文：**

> 「The copied v4 signature no longer covers the new kernel (the AVB hash is stale either way: zeroed…」

**→ 签名字节在，但它对新内核的哈希是陈旧的。** 这与我早先说的「无签名可破坏」在**后果上不同**：
正确表述是「**签名块保留但 AVB 哈希陈旧**」，不是「没有签名」。

---

## 我为什么会读错

**我先在核验脚本里用 `struct.unpack_from('<I', d, 1580)` 得到 4096（正确），
后来在另一段算字段表时把 `1580` 之后的 `1584` 当成下一个字段起点。**

**而**我写文档时用了后者**，并据此推出「无签名可破坏」的结论 —— 这是**从一个错误的读取位置推出一个错误的结论**。**

**教训：boot v4 header 的最后一个字段就在 `1580`，`1584` 已是 padding；核验脚本与文档必须用同一个偏移常量。**
