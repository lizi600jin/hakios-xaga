# 里程碑 6k · loader 通道打通了一半，以及一个测量错误（Trial774）

2026-11-22。**设备正常，安卓在跑。**

## 一、最重要的发现：我把 adb 连不上当成了崩溃

这一轮我刷了三次（三格实验）。每次都是在刷入后等最多 200 秒，`adb get-state`
没返回 `device`，我就记成"崩了"。

**你告诉我：这轮你根本没碰手机，手机正常回到安卓。**

我读了 HLOG，确认了：

```
6667 行日志，时间跨度 19.0 .. 438.3 秒
MiniIOMobileFramebuffer: 51 frames in 5001 ms (10 a second)   ← iOS 桌面在画
guard magic=0x554c5345 version=1 trial=740 state=0            ← 启动 UNUSED
return-gate ... state=2 allowed=1                              ← 正常归还
```

**这个内核完全健康。** 它跑了 438 秒，租约从未被毒化。

### 这意味着什么

**本次会话里"十二次崩溃"的计数是错的。** 其中有多少真的是内核挂了、
有多少只是 adb 没及时连上，我不知道。这可能推翻我这一轮做的很多判断。

### 我漏掉的检查

- 看手机在不在 USB 上（`lsusb`）
- 看 loader 的屏幕输出
- 给 adb 两分钟以上

**一个正在画桌面的手机不是挂了的手机。**

## 二、loader 通道其实早就写好了

查 `loader-src/xnuloader/loader.c` 发现：

| 组件 | 状态 |
|---|---|
| `struct loader_block`（版本 3，协议） | ✅ 已存在 |
| `block_start()` | ✅ 已存在 |
| `block_poll()` 在主循环里 | ✅ 已在跑 |
| `ufs_shared_pa=` 传参 | ✅ 已实现 |
| **`ufs=2` 这个开关** | ❌ **只差这一个** |

内核侧 `bsd/dev/hakios.ufs.c` 是 `optional hakios_ufs`，从未被编译。

我把它改成 `standard`、关掉 `hakios.stubs.c` 的空实现，**链接通过、能启动**。

## 三、三格实验作废

原计划：

| 格 | 内核含 ufs.c | loader ufs=2 | 结论 |
|---|---|---|---|
| 1 | 否 | 是 | "崩" |
| 2 | 否 | 否 | "崩" |
| 3 | 否 | 否 + rc 空 | "崩" |

**三格全是崩溃，这本身就说明问题在测量方法上，不在变量上。** 我当时没想到这一层。

现在知道：格3 的内核是健康的。所以格1、格2 很可能也健康，只是 adb 没连上。

## 四、下一步（必须重做）

**三格实验重新做，判据换成：**

1. HLOG 的 `marker` 是否为 0（内核写没写日志）
2. HLOG 里 `state` 从 0 到 2 的转移
3. 屏幕上的实际内容
4. `lsusb` 里有没有设备

**而不是 adb 是否在 200 秒内返回。**

然后用同样的判据跑一次 `ufs=2` + `xnusys_ufsdev` 的读测试。

## 五、设备当前状态

`boot_a` 是 `ba12af84…`，即 `ufs=2` + `hakios.ufs` 那一版，**不是原厂**。
安卓正常启动。

恢复原厂只需一次 `fastboot flash boot_a`，本会话已做过多次。
这一轮没恢复是因为你要我先读日志并推送。

## 六、教训

**把"没观测到"当成"观测到失败"，是这一轮最严重的错误。**

它导致：
- 三格实验白做
- 上一轮的"十一次失败"里可能有很多不是失败
- 我基于错误前提做了大量代码改动
