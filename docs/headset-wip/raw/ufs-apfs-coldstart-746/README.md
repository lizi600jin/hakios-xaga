# 里程碑 5 · 冷启动读一份真实资源（Trial746）

2026-11-21。两次独立启动，xaga，`boot_a`，恢复原厂后 64 MiB 逐字节相同。

## 读的不是测试文件

目标是从系统镜像里挑的一份真实资源：

```
/System/Library/CoreServices/IconsetResources.bundle/GenericForeground_256@2x.png
```

19577 字节、未压缩、一个 extent（5 个块全在 29559 起的连续位置）。主机独立读同一份文件算出
`fnv1a = bbdbcb6f`、`sha256 = 26280a17…`，作为比对基准。

## 两次启动的结果

| | 第一次 | 第二次 |
|---|---|---|
| 读到字节 | 19577 | 19577 |
| FNV-1a | `bbdbcb6f` | `bbdbcb6f` |
| 头 8 字节 | `\x89PNG` | `\x89PNG` |
| 注册到首次读取 | 3866 µs | 3869 µs |
| 设备服务读取次数 | 45 | 45 |
| 覆盖块数 | 72 | 72 |
| 结论 | PASS | PASS |

两次都是同一份内容、同样的命令数。首次读取时间差 3 µs。

## 数字从哪来

不是程序自己报的。设备侧有三个计数器（`hakios.xnusys_blk.c`）：

- `first_ns`：从设备注册到第一次返回数据的读取
- `reads`：之后服务的请求数
- `blocks_read`：这些请求覆盖的块数

用户程序只能通过 `XNUSYS_STATS` ioctl 把它们读出来，改不了。

## 45 次读取、72 个块的含义

读 19577 字节要 5 个数据块，其余是文件系统自己的元数据遍历：容器超级块、omap、卷超级块、
文件系统树的多层内部节点、inode、extent 记录。45 次读取说明缓存起了作用——枚举目录时读过的
节点没有再读第二遍。

## 顺带确认

`xnusys-blk: first read after 3866 us, offset 0 len 4096` —— 第一次读落在偏移 0，是挂载时读容器
超级块，符合预期。
