## 这一版加的三样东西

### 1. 映射只做一次

上一版每次读数都调 `ml_io_map`，每 10 秒泄漏一页内核虚拟地址。
现在 `i2c_wrap_s_cached` 和 `i2c7_base` 是文件级静态变量，第一次用时映射、之后一直用。

`ml_io_map` 在整个驱动里没有配对的 unmap，所以「映射一次」不是优化，是唯一正确的做法。
一个每 10 秒漏 4 KB 的线程，一天就是 34 MB 的虚拟地址空间。

### 2. 周期是 10 秒，不是 1 秒

电量变化以分钟计。每读一次是 9 笔 I2C 事务，抢的是同一条总线。
10 秒足够看出充电在爬，又几乎不占总线。

### 3. 多读了两个寄存器

| 命令 | 名字 | 用途 |
|---|---|---|
| `0x10` | RemainingCapacity | `charge_uah`，比 `full × soc` 少一次取整 |
| `0x0a` | BatteryStatus | bit5 = FC（满电），bit6 = DSG（放电） |

**状态不再靠电流的正负猜。** 上一版「电流 > 0 就是充电」，对一块充满后吃涓流的电池会误判成「充电中」。
现在直接读芯片的标志位：

```
status 0x40 = 0b0100_0000  →  bit6 DSG = 1  →  放电
```

和 `current = -75 mA` 一致。两路独立的信息对上了。

## 一个低级的坑

改代码时我用「整体替换 `report_battery` 之后的所有内容」这个做法，
把 `hakios_mt6895_i2c_start()` 的尾巴连同 `i2c=3` / `i2c=4` 的调用块一起删掉了。

表现是：`i2c=4` 的 boot-arg 在 loader 里明明对的，但驱动只 dump 不读表也不起线程。

查了很久才想到去看文件末尾——那里直接就是 `battery_thread`，`start()` 的函数体已经没了。

**用「替换到文件末尾」改代码时，被删掉的东西不会有任何报错。**

## 每条打印两次

hlog 里每一行电池读数都成对出现，时间戳差 0.0 秒。

不是两个线程（间隔严格 10.0 秒，成对的两条差 0 秒），也不是 `HakiosBatteryReport` 里又打印了一次
（那个函数里没有 printf）。看起来是 hlog 环形缓冲的读取方式导致的重复，不影响功能，没再追。

## 还没做的

- `battery_test` 没编译。它依赖 CoreFoundation 和 IOKit，要走 `build.sh`，
  而本机没有 iOS SDK。要在设备上验 `powerd` 和状态栏，得先把 `obj/battery_test` 编出来。
- `i2c=4` 还是手动开的，没做成默认。做成默认需要先确认 `battery_test` 能读对。
- 充电状态（`external`）来自 DSG 位，但「插着充电器且没在放电」和「没插充电器」都是 DSG=0，
  这两个分不开。要分开得问 `mt6375` 的充电器状态。
