## 4. 按「性价比」排的修复顺序（我的判断）

| 序 | 做什么 | 为什么 | 预估工作量 |
|---|---|---|---|
| **1** | **UFS 只读探针**（已写好，未上机）| **零风险，一次就能知道 LK 有没有保留控制器状态** | **已完成代码，等上机** |
| **2** | **UFS 接管 + 挂载 APFS** | **解开最大死结：用户态/图形/音频全依赖它** | **大**（但主线 Linux 已跑通，有参照）|
| **3** | **真音频通路**（adsp→sound→speaker）| 用户最关心；且主线 Linux 已有完整 mixer 序列可抄 | 大 |
| **4** | CPU 调频（先做只读探针上机）| 影响续航与流畅度，但不阻塞功能 | 中 |
| **5** | GPU 硬件加速 | 现在 CPU 软绘 10 fps | 大 |
| **6** | Wi-Fi/BT | 日用必需但可最后 | 中 |
| **7** | 基带 | 最末期 | 很大（要重定位地址 + 固件加载）|

## 5. 三条重要说明

### 5.1 「没编译」不等于「代码写好了」

**23 个驱动的注释写着 POCO X5 Pro (redwood)，只有 6 个提到 xaga。**

**`mpss`（250 KB）、`sound`、`speaker`、`wifi` 的地址都是 redwood 的。**

**→ 这些要重定位，不是改个 config 就能编。**

### 5.2 「已编译」不等于「在工作」

**`mali610` 编进去了，但画面还是 CPU 软绘。**
**`mt6895_cpufreq` 编进去了，但没上机。**

### 5.3 「logbook 零次」不等于「子系统没代码」

**`baseband`/`SEP`/`AOP`/`CLPC` 在 logbook 里 0 次，是因为它们的驱动未编译，
而不是代码不存在。**
