# 里程碑 5b · 读错误恢复取证，阶段 4 补齐（Trial747）

2026-11-21。xaga，`boot_a`，恢复原厂后 64 MiB 逐字节相同。

## 读错误之后设备还活着

阶段 4 最后一条验收是"一次读错误后，能释放请求并返回原厂链路"。后半句每轮都以逐字节读回收尾，
缺的是前半句：一个**真的会失败**的读，以及它之后的证据。

失败的读是越过分区末尾那一个——真实边界，不是注入的故障：

```
xnusys-readerr: read past the end -> -1 (lseek 2492203008)
xnusys-readerr: after the error, read 7814 bytes, fnv=30630d20
xnusys-readerr: PASS
```

第一个 `-1` 是它没有把不存在的字节交出来。第二行是同一个启动里，同一个挂载上的另一个文件照常
读出 7814 字节，FNV 与主机独立算的 `30630d20` 相同。

同一次启动里接着发生的：

```
xnusys-blk: unmount /redwood/lib -> 0
return-gate magic=0x554c5345 version=1 trial=740 state=2 allowed=1
```

`state=2` 是 `UR_RESTORED`，`allowed=1` 是守卫放行。**一条完整的链路**：读错误 → 设备仍可用 →
卸载 → 所有权归还。
