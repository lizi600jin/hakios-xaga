## 4. 三个层次的差距（这是我理解的关键）

### 层次 1：能启动 + 能显示（**已达成**）

**XNU 起来了，launchd 起来了，framebuffer 出帧了，触控响应了。**

**这一层的限制**：显示是**内核里直接写 framebuffer**，
不是通过 iOS 的 WindowServer/CoreAnimation 栈。

### 层次 2：iOS 用户态服务真正工作（**未达成**）

**要有**：真正的图形栈、音频栈、存储、电源管理。

**卡在哪（我的判断，需 Codex 确认）**：
- launchd spawn 了 25 个服务，但**没有它们初始化成功的证据**
- 没有 coreaudiod → 没有音频会话
- 没有 ans2 → 没有真正的文件系统
- 没有 CLPC → CPU 频率固定，性能与功耗都不对

### 层次 3：完整 iOS 环境（**远未达成**）

**基带、SEP、通话、应用生态。**

---

## 5. 我看到的三个可能瓶颈（按影响排序）

| # | 瓶颈 | 影响 | 难度 |
|---|---|---|---|
| **1** | **ans2（存储协处理器）** | **没有它就没有真正的文件系统** —— 所有依赖文件的服务都起不来 | 高 |
| **2** | **CLPC / PMGR（电源与调频）** | CPU 频率固定 → 性能差、功耗高、可能不稳定 | 中高 |
| **3** | **SEP（安全协处理器）** | 大量系统服务依赖它做认证 | 高 |

**GPU 反而可能不是当前最大瓶颈** —— 现在画面能出（10 帧/秒），只是走 CPU 路径。
