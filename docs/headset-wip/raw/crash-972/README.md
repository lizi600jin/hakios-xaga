# 一次自己写出来的内核崩溃（`boot-972`）

2026-11-26。记下来是因为这两个错误都不涉及硬件，都是我改代码的方式造成的。

## 崩溃本身

`boot-972` 加了 `i2c-6` 的只读扫描（读背光 IC `0x11` 的 `0x00..0x10`）。
进 XNU 后 `hakid` 不应答，USB 掉线，需要手动长按电源才回得来 fastboot。

### 根因：空指针解引用

```c
/* peek_c6 里读亮度那两个寄存器，我传了 NULL */
i2c_smbus_byte(i2c6_base, 0x11u, 0x04u, &lo, NULL, NULL, NULL);
                                              /* ↑ statp */

/* i2c_wait_done 里 */
if ((stat & (I2C_INTR_COMP | I2C_INTR_ERRORS)) != 0u) {
        *statp = stat;        /* ← 解引用 NULL */
```

**我给 `fifop` 和 `rawp` 都写了 NULL 检查，唯独漏了 `statp` 也被解引用。**

同一个函数里，三个输出参数，我保护了两个。

修法：`i2c_wait_done` 里 `if (statp != NULL)`，`i2c_smbus_byte` 里用本地变量兜底再转出去。

## 第二个错：替换到文件末尾吃掉了函数体

我用「整体替换 `report_battery` 之后的所有内容」这个做法改代码，
把 `hakios_mt6895_i2c_start()` 的尾巴连同 `i2c=3` / `i2c=4` 的调用块一起删了。

表现：loader 里 `i2c=4` 明明是对的，驱动却只 dump、不读电量计、不起线程。
查了很久才想到看文件末尾——那里直接就是 `battery_thread`，`start()` 的函数体已经没了。

**替换到文件末尾时，被删掉的东西不会有任何报错。**
编译能过，因为它用的是声明，不是定义。

判断办法：多余地检查一遍关键函数的计数。

```sh
grep -c "^hakios_mt6895_i2c_start" file.c     # 应该是 1
```

## 第三个错：同一个符号定义两次

修 `peek` 的时候我把新版本追加到文件末尾，忘了旧的还在中间。
编译报 `redefinition of 'hakios_mt6895_i2c_peek'`。

这个至少编译器会拦住，不像前两个。

## 代价

操作者手动长按电源恢复。这已经是我第二次把设备弄到需要动手了
（第一次是 `disp_pwm0` 的盲写）。

两次的共同点：**我在没有验证的情况下改动了不该动的东西。**

第一次是没验证就写寄存器。第二次是没验证就把指针传成 NULL。
第二次更没道理——那是个纯软件的 bug，跟硬件一点关系都没有。

## 之后的规矩

操作者把代码这部分交给了 Neon 来写，我只做刷机、探测、验证、报现象。

这样至少「谁写的 bug 谁负责想清楚」，而我这一侧的活是可以在出错时被看见的
（刷机、读日志、报现象——错了立刻能从现象上看出来）。
