Why /private/var/vm had to go
-----------------------------
vm_compressor_backing_store.h, !XNU_TARGET_OS_OSX branch:

    #define MIN_SWAP_FILE_SIZE   (64 * 1024 * 1024ULL)
    #define MAX_SWAP_FILE_SIZE   (128 * 1024 * 1024ULL)

vm_compressor_backing_file.c:64:

    vnode_open(path, (O_CREAT | O_TRUNC | FREAD | FWRITE), S_IRUSR|S_IWUSR, 0, vp, ctx)

The volume is 174 MiB with 162 MiB free, so a 128 MiB swapfile would fit on the first
attempt and take 79% of it. With the directory absent, vnode_open fails with ENOENT and
the swap thread goes on failing exactly as it always did, writing nothing.

The eight plists and where they come from
-----------------------------------------
var.skel carries eight 'f' records:

    f 644 501 501 /private/var/mobile/Library/Preferences/com.apple.springboard.plist  /var/mobile/Library/Preferences/com.apple.springboard.plist

in_image() prefixes /redwood, so the source is
/redwood/var/mobile/Library/Preferences/... -- the read-only system image, not the memory
disk's /var. That is why replacing /var with a symlink cannot break the copy.

What is still not done: /var does not point at /private/var
----------------------------------------------------------
    wifid[8:232] store URL: file:///var/root/Library/Caches/com.apple.wif...

/var is still the memory disk's own directory (drwxr-xr-x /redwood/var), so anything
written under /var/ rather than /private/var/ is lost on the next boot. Standard iOS has
/var -> private/var. var.skel has no such entry, and /var already exists as a non-empty
directory, so symlink() would return EEXIST.
