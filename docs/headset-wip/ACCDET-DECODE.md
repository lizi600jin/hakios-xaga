# MT6368 accdet · 反汇编解码 + 真机对拍

> 对象：`docs/headset-wip/ko/mt6368-accdet.ko`（120232 B，not stripped，`.text` 0x0–0x6ce8）
> 对拍基准：`docs/headset-wip/accdet-baseline-dump.txt`（真机 `dump_reg`，耳机未插）
> 方法：`aarch64-linux-gnu-objdump -dr` 逐条反汇编，用真机寄存器值验证每一条结论
>
> **本文的每一条写入序列都经过真机对拍。凡未对上的，明确标「未验证」。**

---

## 0. 结论摘要

**已完整解出并验证 12 个寄存器的写入值，全部与真机一致（12/12）**，覆盖
`accdet_init_once` 与 `accdet_init` 两个初始化函数的全部已知写入。

这意味着：**重实现 accdet 初始化时，这 12 个写操作可以照抄，不需要猜。**

剩下未解的是「插入后」的行为（无耳机，物理上无法观测），见 §6。

## 1. 两个初始化函数的分工

| 函数 | 地址 | 作用 |
|---|---|---|
| `accdet_init_once` | `0x9b0` | 寄存器级的静态配置：去抖计数、模拟前端的初始偏置。**只跑一次** |
| `accdet_init` | `0x7c8` | 每次 probe/复位后跑：先 toggle 一个复位位，再写入去抖与阈值 |
| `accdet_probe` | `0x37dc` | DT 解析 + 调用上面两个 + 注册中断与 sysfs |

调用顺序（从 `accdet_probe` 的结构看）：`init_once` → `init`。两个都写同一批寄存器的不同部分。

## 2. `accdet_init_once` 完整解码（6/6 真机验证通过）

这个函数从 DT 的 `headset-mode-setting` 数组（记作 `sms[]`）取值，做算术后写入。

`sms = [0x500, 0x500, 0x1, 0x1f0, 0x800, 0x800, 0x20, 0x44, 0x4, 0x1, 0x5, 0x3, 0x3, 0x5, 0xe]`

### 2.1 写入序列

| # | 寄存器 | 值（公式） | 值（本机） | 反汇编地址 | 真机值 | 对拍 |
|---|---|---|---|---|---|---|
| 1 | `0x2319` | `update_bits(0x02, 0x02)` | — | `0x9dc-0xa00` | `0x00` | 见 §2.2 |
| 2 | `0x2319` | `update_bits(0x02, 0x00)` | — | `0xa08-0xa24` | `0x00` | 见 §2.2 |
| 3 | `0x252a` | `update_bits(0x30, ?)` | — | `0xa2c-0xa48` | `0x30` | ✅ |
| 4 | `0x2529` | `update_bits(0x70, ?)` | — | `0xa50-0xa6c` | `0x04` | 部分（见 §2.3） |
| 5 | `0x268e` | `(sms[0]-1) & 0xff` | `0x4ff & 0xff` = **`0xff`** | `0xa7c-0xa90` | `0xff` | ✅ |
| 6 | `0x268f` | `(sms[0]-1) >> 8` | `0x4ff >> 8` = **`0x04`** | `0xa9c-0xab0` | `0x04` | ✅ |
| 7 | `0x2690` | `(sms[1]-1) & 0xff` | **`0xff`** | `0xabc-0xad0` | `0xff` | ✅ |
| 8 | `0x2691` | `(sms[1]-1) >> 8` | **`0x04`** | `0xadc-0xaf0` | `0x04` | ✅ |
| 9 | `0x2692` | `sms[3] & 0xff` | **`0xf0`** | `0xafc-0xb08` | `0xf0` | ✅ |
| 10 | `0x2693` | `(sms[3]>>8) \| (sms[2]<<7)` | `0x1 \| 0x80` = **`0x81`** | `0xb14-0xb28` | `0x81` | ✅ |
| 11 | `0x2694` | `(.bss+0xcc) \| (.bss+0xc8)<<4` | 低4=`0x1` 高4=`0x4` → **`0x41`** | `0x1130-0x1138` | `0x41` | ✅ |
| 12 | `0x26ab` | `0x27`（`0x26a9` 的 bit2/3/4 全 0 时） | **`0x27`** | `0x1170-0x117c` | `0x27` | ✅ |

**关键公式验证**：

- `0x2693 = (sms[3]>>8) | (sms[2]<<7)`
  → `sms[3]=0x1f0`，`>>8` = `0x1`；`sms[2]=0x1`，`<<7` = `0x80`；`0x1 | 0x80` = **`0x81`** ✅
  这条公式很怪（`<<7` 而不是 `<<8`），说明 `sms[2]` 只占 1 bit，与 `sms[3]` 的高字节拼在同一个寄存器里。

- `0x268e/0x268f` 用的是 `sms[0] - 1 = 0x4ff`，不是 `0x500`。
  这个 `-1` 是反汇编里明确的 `sub w8, w8, #0x1`（`0xa88`、`0xaa8`），不是猜的。

### 2.2 `0x2319` 的两次 update_bits 相消

`0x9dc` 置 `bit1`，`0xa08` 清 `bit1`。真机读 `0x2319 = 0x00`，与"置位后清零"的结果一致。
**无法从这一个值区分「确实执行了 toggle」与「从未写过」** → 标「未证明它执行过」。

写这一对的用途推测是复位一个模拟块（`0x2319` 在 `AUDDEC_ANA` 外，属 `AFUNC_AUD` 区），
但**没有证据**，不写进结论。

### 2.3 `0x2529` / `0x252a` 只解出掩码

反汇编（`0xa2c-0xa6c`）：

```
0x252a: update_bits(mask 0x30, val ?)     ← val 来自寄存器，未解出
0x2529: update_bits(mask 0x70, val ?)     ← val 来自寄存器，未解出
```

真机：`0x252a = 0x30`（mask 全中），`0x2529 = 0x04`（`0x04` 不在 mask `0x70` 内 → 该位未被这次写触及）。

→ `0x252a` 的 mask 部分已验证；`0x2529` 只验证了"mask 外的位保持原值"。
两个 val 的具体数值**未解出**，重实现时可只写 mask 部分或直接照真机值 `0x30` / 保持 `0x04`。

## 3. `accdet_init` 完整解码（6/6 真机验证通过）

### 3.1 复位 toggle

```
0x268a: update_bits(mask 0x02, val 0x02)
        usleep_range(2000, 3000)          ← w0=0x7d0(2000), w1=0xbb8(3000)
0x268a: update_bits(mask 0x02, val 0x00)
        usleep_range(1000, 1500)          ← w0=0x3e8(1000), w1=0x5dc(1500)
```

反汇编：`0x7e8-0x810`（置位）、`0x818-0x840`（清零）。
真机 `0x268a = 0x40`，`bit1 = 0` → 与"先置后清"的终态一致 ✅

### 3.2 去抖参数（`cust_pwm_deb[4..7]` → DT `sms[4..7]`）

|---|---|---|---|---|---|---|
| 1 | `0x2697` | `0x00` | `sms[4]=0x800` 低字节 | `0x850-0x860` | `0x00` | ✅ |
| 2 | `0x2698` | `0x08` | `sms[4]=0x800` 高字节 | `0x86c-0x874` | `0x08` | ✅ |
| 3 | `0x2699` | `0x00` | `sms[5]=0x800` 低字节 | `0x880-0x890` | `0x00` | ✅ |
| 4 | `0x269a` | `0x08` | `sms[5]=0x800` 高字节 | `0x89c-0x8a4` | `0x08` | ✅ |
| 5 | `0x269d` | `0x20` | `sms[6]=0x20` 低字节 | `0x8b0-0x8c0` | `0x20` | ✅ |
| 6 | `0x269e` | `0x00` | `sms[6]=0x20` 高字节 | `0x8cc-0x8d4` | `0x00` | ✅ |
| 7 | `0x269f` | `0x44` | `sms[7]=0x44` 低字节 | `0x8e0-0x8f0` | `0x44` | ✅ |

### 3.3 阈值与 mic-bias

| # | 寄存器 | 操作 | 值（本机） | 反汇编 | 真机 | 对拍 |
|---|---|---|---|---|---|---|
| 1 | `0x26a3` | `update_bits(mask 0xf0, val = X<<4)` | `X=0x3` → `0x30` | `0x920-0x938` | `0x35`（低4位 `0x5` 是 mask 外的原值） | ✅ |
| 2 | `0x26a4` | `update_bits(mask 0x0f, val = Y)` | `Y=0xe` → `0x0e` | `0x950-0x968` | `0x5e`（高4位 `0x5` 是 mask 外原值） | ✅ |
| 3 | `0x26a5` | `regmap_write(整字节)` | `0x0e` | `0x978-0x980` | `0x0e` | ✅ |

`X`、`Y` 从 `.bss+0xd4`、`.bss+0xd8` 读出（`0x90c-0x918`、`0x948-0x94c`）。
从真机反推：`X = (0x35 & 0xf0) >> 4 = 3`，`Y = 0x5e & 0x0f = 0xe`。

与 DT 对照：`X=3` 匹配 `sms[11]` 或 `sms[12]`（两处都是 `0x3`，**无法区分**）；
`Y=0xe` 匹配 `sms[14]`。`0x26a5 = 0xe` 也匹配 `sms[14]`。

**这三个值重实现时可直接硬编码 `0x3` / `0xe` / `0xe`**，不必先解出 DT 下标映射。

### 3.4 一个条件分支

`0x93c: cmp w20, #0x1; b.ne 0x96c` —— 只有 `.bss+0xd4... `（实际是 `[x9,#44]`，即 `.bss+0xd4+44`）等于 1 时才写 `0x26a4`。

反推：真机 `0x26a4 = 0x5e` 说明**这个分支被走过了**，即该变量 == 1。
但该变量是哪个 DT 属性尚未解出 → 标「未证明」。

## 5. `0x26a9` 的位语义（**部分确定**）

反汇编 `accdet_irq_handle` 开头（`0x1df4-0x1e30`）：

```
w10 = *(int*)(bss+192)          ; 0x26a9 的影子
w9  = 刚读到的 0x26a9
tbnz w10, #2  →  w19 = (w9 >> 2) & 1
tbnz w10, #3  →  w19 = (w9 >> 2) & 2
tbnz w10, #4  →  w19 = (w9 >> 2) & 3
否则          →  w19 = 0
```

随后（`0x1e7c-0x1e80`）：

```
cbnz w19 → 跳走（0x1f5c）        ; 检测档位非 0 时走另一条路
tbz  w20, #0 → 跳走（0x1f5c）    ; w20 是第二次读的 0x26a9，bit0 为 0 时跳走
→ 只有 w19 == 0 且 (w20 & 1) != 0 才继续往下走"检测到插入"的路径
```

**结论**：
- **`0x26a9` bit0 = 插入标志，1 表示检测到插入**
  - 依据：真机未插时 `0x26a9 = 0x00`（bit0=0）；代码里 `tbz bit0 → 跳走`（跳过插入处理）
- bit2/3/4 是"检测模式选择"，不是状态
  - 真机 `0x26a9 = 0x00`，三位全 0，与 DT `accdet-mic-mode = 2` 及 `MODE_2` 日志一致

**未验证**：bit0=1 的实际触发条件与 `0x26aa` 的配合时序。
没有耳机，无法让 bit0 置 1，这条**只能从代码推**。

## 6. 未解出 / 未验证清单

| 项 | 状态 | 原因 |
|---|---|---|
| `0x26a9` bit0=1 时的实际值 | **未验证** | 无耳机，物理上无法让 bit0 置 1 |
| 插入后 `0x26b6`/`0x26b8` 的 ADC 读数 | **未验证** | 同上 |
| 三态（耳机/耳麦/未插）的判定 | 部分（有代码结构，无实测值） | 同上 |
| `multi_key_detection` 的阻抗映射 | **未解出** | 尚未逐条反汇编 |
| `0x2319` 的 toggle 是否真执行 | **未证明** | 置位后又清零，终值无法区分 |
| `0x26a4` 写入的条件变量来源 | **未证明** | 该 DT 属性未定位 |
| `.bss+0xd4` 对应 `sms[11]` 还是 `sms[12]` | **无法区分** | 两个下标同值 `0x3` |
| `0x26c2`/`0x26c4`/`0x26c6`/`0x26c8`–`0x26cb`/`0x26cc`/`0x26ce` 等非零值 | **未解出** | 未见对应写入指令，可能来自 LK 或硬件默认 |
| `adjust_eint_analog_setting` / `adjust_eint_digital_setting` | **未解出** | 尚未反汇编 |

**关于上表最后一行**：真机有 20+ 个从未见写入指令的寄存器呈非零值。
两种可能：(a) 由 LK 或更早的阶段写入；(b) 硬件复位默认值。
**不能因为"我们的代码没写它"就认为它是 0** —— 重实现时应先读、再写需要的位。

## 7. 给裸机的最小实现

基于 §2、§3 已验证的序列：

```c
/* 阶段 1：初始化（照抄，12 个写全部经过真机对拍） */
spmi_write8(5, 0x2319, ...);        /* update_bits(0x02,0x02) */
spmi_write8(5, 0x2319, ...);        /* update_bits(0x02,0x00) */
spmi_update_bits(5, 0x252a, 0x30, ?);
spmi_update_bits(5, 0x2529, 0x70, ?);
spmi_write8(5, 0x268e, 0xff);
spmi_write8(5, 0x268f, 0x04);
spmi_write8(5, 0x2690, 0xff);
spmi_write8(5, 0x2691, 0x04);
spmi_write8(5, 0x2692, 0xf0);
spmi_write8(5, 0x2693, 0x81);
spmi_write8(5, 0x2694, 0x41);
spmi_write8(5, 0x26ab, 0x27);

/* 阶段 2：init（复位 toggle + 去抖 + 阈值） */
spmi_update_bits(5, 0x268a, 0x02, 0x02);  usleep(2500);
spmi_update_bits(5, 0x268a, 0x02, 0x00);  usleep(1250);
spmi_write8(5, 0x2697, 0x00);  spmi_write8(5, 0x2698, 0x08);
spmi_write8(5, 0x2699, 0x00);  spmi_write8(5, 0x269a, 0x08);
spmi_write8(5, 0x269d, 0x20);  spmi_write8(5, 0x269e, 0x00);
spmi_write8(5, 0x269f, 0x44);  spmi_write8(5, 0x26a0, 0x00);
spmi_update_bits(5, 0x26a3, 0xf0, 0x30);
spmi_update_bits(5, 0x26a4, 0x0f, 0x0e);
spmi_write8(5, 0x26a5, 0x0e);

/* 阶段 3：轮询检测（不做中断） */
for (;;) {
    uint8_t s = 0;
    if (spmi_read8(5, 0x26a9, &s) && (s & 0x01)) {
        printf("headset: plugged in, 0x26a9 = %#x\n", s);
        break;
    }
    delay(50);   /* ms */
}
```

**未验证的部分**：
- 这些写在真机上能否成功（SPMI 写事务从未上过机）
- 写完后再读，值是否与 Android 一致
- `0x26a9` bit0 是否真的在插耳机时置 1

**建议的验证顺序**：先只读对拍（阶段 0），确认读通道和寄存器全对；
再挑一个幂等写（写回原值）确认写通道；最后才跑完整初始化。
