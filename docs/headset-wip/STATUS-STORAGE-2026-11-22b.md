## 缺的一步

**让某个东西能安全地读到 `/dev/xnusys_var`。**

十一次尝试，每次都让 loader 的 guard 报"所有权未归还"，租约停在 `state=3`（POISONED）。

关键发现：**唯一成功那次（439 秒，iOS 桌面正常）`zone_read` 被调用 0 次。**
所以"读路径"从来没被验证过。

## 两条路

### 路 A：修 `xnusys_var` 的读路径
十一次失败，每次都改一处就刷机。两个真 bug 已修（`d_psize`、poison 语义），
但仍然崩。**继续盲试没有意义。**

### 路 B：用 `hakios.ufs.c` 的共享页通道
- 内核不碰控制器，由 loader 代为读写
- 不碰租约，所以不会搞坏租约
- `var_store` 已经在用这条路
- 已编进内核并编译通过
- **缺 loader 侧配套**：分配共享页、传 `ufs_shared_pa`、core 0 循环处理请求

**这条路架构上正确，但要一整轮的工作量。**

## 容量账（实测）

| 项 | 大小 | 状态 |
|---|---|---|
| `xnusys` 数据卷窗口 | 174 MiB | 已写好 HFS+，读不通 |
| `xnusys` APFS 容器 | 2.32 GiB | 只读，工作正常 |
| `userdata` | 103.98 GiB | 安卓的，**块层 AES-XTS 加密**，XNU 读不到明文 |
| **XNU 当前持久存储** | **0 字节** | `/private/var` 是内存盘 |

DSU 那条路已实测否掉：`dm-50` 不是 `sdc86` 的线性映射，F2FS 超级块在 `dm-50` 上
可读（`10 20 f5 f2`）、在 `sdc86` 上是随机字节。元数据加密坐在块层。

## 174 MiB 够不够

codex 提醒过不能用骨架推断。
