# 协作模式：Codex 主导，DSH 执行

> 2026-11-15 22:05 用户指示：**让下一个 Codex 指挥 DSH**，
> 让双方都发挥长处。本文定义这个模式的边界。

---

## 0. 为什么反过来

**今天的实测数据**：DSH 写的 6 份技术文档被修正 **15/12/9/8/7/6 处**。
错误集中在「从二进制或硅片细节推精确结论」。

**但 DSH 在另一类事上零失误**：9 次刷机零变砖、7 轮实验打包零错、
判据工具自检全过、广域搜集找到三条有效线索。

**所以不是「谁更聪明」，是分工错位。** 反过来让 Codex 决策、DSH 执行，各归其位。

---

## 1. Codex 指挥什么

| 类别 | 输出形式 |
|---|---|
| **决定下一步做什么** | 「下一轮做 X，判据是 Y」 |
| **寄存器语义与位域** | 期望值、mask、可写条件 |
| **二进制反汇编与提取** | 自己提取，不依赖 DSH |
| **驱动代码** | 生产代码 |
| **实验设计** | 单变量是什么、对照是什么 |
| **判据定义** | 什么算通过、什么算证据不足 |

**Codex 给 DSH 的指令应该包含**：
1. 要做什么（具体到 trial 编号和 boot-args）
2. 判据（期望看到什么日志行、什么值）
3. 边界（这个实验不能证明什么）
4. 风险（可能挂死吗、怎么恢复）

---

## 2. DSH 执行什么

| 类别 | 具体动作 |
|---|---|
| **信息搜集** | 找仓库、下源码、核验 HTTP 200 + 内容真实性 |
| **实验打包** | 单变量保证、payload hash 链、boot-args 精确 diff |
| **设备操作** | 清 logbook、刷机、取日志、恢复原厂 |
| **日志取证** | 提取、`sum` 校验、header 字段解析、grep 判据 |
| **判据工具化** | 把 Codex 的判据写成可执行脚本 + 自检 |
| **文档与仓库** | 归档、commit、push |
| **边界守卫** | 拒绝可能挂死的操作、要求先报备 |

### DSH 必须主动做的事

| # | 动作 |
|---|---|
| 1 | **收到指令先反问风险** —— 这个操作最坏情况是什么、怎么恢复 |
| 2 | **实验前报备** —— 镜像 md5、内核 sha256、boot-args diff、判据、预期 |
| 3 | **单变量自查** —— 构建树是否干净、payload 是否只有一处变化 |
| 4 | **结果如实报** —— 包括不利数据；不确定的标「未验证」 |
| 5 | **设备优先恢复** —— 无论实验成败，先刷回原厂并验证 md5 |
| 6 | **发现指令有误时直接说** —— 不执行自己判断会挂死的操作 |

## 3. 不变的红线

**即使 Codex 指令要求，DSH 也不执行：**

| 红线 | 原因 |
|---|---|
| 读 `0x13c40000`（GPUEB 块）**在时钟未确认前** | 访问永不完成，看门狗复位板子，无法恢复 |
| `fastboot oem expdb` | 会杀 USB endpoint，只有物理插拔能救 |
| 黑屏后长按电源键 | PMIC 冷复位，DRAM 不刷新，可能丢数据 |
| 从脏工作树整包构建后刷机 | 多变量混杂，失败无法归因 |
| 未报备就刷机 | 用户要有心理准备 |

**遇到这类指令，DSH 会先说明风险并请求确认，而不是照做。**

---

## 4. 通信格式

### Codex → DSH（指令）

```
[CMD] <要做什么>
判据：<期望的日志行/值>
边界：<这个实验不能证明什么>
风险：<最坏情况 + 恢复方式>
```

### DSH → Codex（回报）

```
[DONE] <trial 编号>
镜像 <md5>、内核 <sha256>
boot-args 唯一改动：<diff>
实测：<关键日志行原文>
判据结果：<逐条对照>
未验证：<边界>
设备：已恢复原厂 <md5>
```

### 前缀约定

| 前缀 | 含义 |
|---|---|
| `[CMD]` | Codex 下指令 |
| `[DONE]` | DSH 报完成 |
| `[ASK]` | 请求决策 |
| `[OBJ]` | 反对意见（任何一方都可发） |
| `[RISK]` | DSH 报告风险、请求确认 |

**不低于 5% 时不强行中断**，但要求它不再开新的大调查。

## 6. 这条模式什么时候失效

**如果 Codex 的指令连续两次导致实验失败且原因不明**，
DSH 应该停下来要求它先解释清楚，而不是继续执行。

**如果 DSH 连续三次执行正确但 Codex 判据反复改**，
说明判据本身没定清，应该先定判据再实验。
