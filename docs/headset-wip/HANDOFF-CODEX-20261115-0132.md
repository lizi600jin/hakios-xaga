## 4. PMIF：已实现、已构建，未在手机验证

实现位置：

- `mtk/mt6895/drivers/core/hakios.mt6895_pmif.c`
- `xnu/files/bsd/sys/hakios.pmif.h`
- `mtk/mt6895/drivers/{input,audio,gpu}/` 三个消费者及 conf。

核心：

1. 只复用 `drivers/core/hakios.platform.c` 既有 `hakios_spmi_lock/unlock()`；未新建锁。粒度为单笔完整事务，初始化序列的2ms/1ms延时在解锁之后。
2. 一笔事务所有等待/恢复共享 **100ms deadline + 10000次状态轮询上限 + 10us失败轮询间隔**；旧2ms/20000活动实现已经消失。10us使用有限的时基忙等，不在锁内调用delay/sleep/printf/分配；时基暂停本身有硬顶，冻结计数器也会返回。
3. 100ms是轮询预算；耗尽后仍允许一次有限的STA采样/必要ACK。没有新的恢复预算。不声称能约束一个自身永不返回的MMIO访问，也没有实测手机持锁耗时。
4. 映射请求0x8ff，accessor严格白名单：只读STA/RDATA，只写ACC/WDATA/VLDCLR。真实VM映射会按页取整，不能据此访问0x900等。移除chan参数，消灭越界通道算术。
5. 先检查完整宽度SID/地址/数值再编码，SID只接受4/5；禁写014b、0240。读只在ACK后验IDLE成功后发布*out。写置bit29，只等IDLE，不等WFVLDCLR。
6. 所有失败点合流恢复，包括初始IDLE超时后才迟到的FSM6；仅FSM6补VLDCLR，不写控制器全局reset/gate。
7. pmif_init在锁外ml_io_map、锁内发布，并发第一次初始化的多余映射在锁外按VM页粒度unmap。
8. 停核后的headset_quiesce只发布atomic stop标志，**不取锁、不读写PMIF、不ACK、不恢复寄存器、不printf**。saved_count保留，说明未恢复。不能假设psci停核一定成功；无锁ACK可能抢活跃事务应答，DSH已明确同意完全不做besteffort。
9. 回滚只留在keys worker的初始化/轮询失败路径。keys的SID4读失败也不会跳过headset初始化（B5）。

构建系统：core/conf新增 `driver MT6895_PMIF`；三个消费者均requires它；mt6895.config显式y。没有新增spmi子系统。drivers-check漏掉usb合法子系统的问题已修。
