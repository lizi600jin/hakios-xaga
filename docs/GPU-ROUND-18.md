## (b) 理由与证据

### 1. PROT 三节不等于正常启动必写的所有全局数据

交接第 23–28、42–44、115–117 行把 `0x03000000–0x03040000` 当作正常固件“写全局变量”的代表，并将阴性结果收窄到取指/翻译阶段。缺少的是该固件早期控制流实际访问这个范围的证据。

直接源码与日志显示：

- `/tmp/src-ref/panthor_panthor_fw.c:586–590`：明确因不支持 protected mode 而忽略 PROT 条目。
- `/home/lizi/IOS/work-xaga/k-xaga-16.2/drivers/gpu/mediatek/mali-valhall/gpu/arm/midgard/csf/mali_kbase_csf_firmware.c:555–561`：protected 条目在没有 PMA 时返回成功并跳过；571–583 行将保护分配和普通分配分开。这支持“PROT 的特殊用途”，不支持“所有正常启动都会访问它”。
- `out/round-8-support/trial-692-mali.txt:80–86`：`0x02000000–0x02040000` 存在可写非 PROT 区，且 section 3/4 同样是文件数据长度为零的段。
- 同一日志第 93、97、101 行才是 flags `0x2b` 的三节 PROT；第 104 行还有可写 shared 区 `0x04000000–0x04094000`。
- `out/trial-692-review.md:36` 已明确提醒：SEC_PROT 不能等同普通 `.bss`，数据长度为零只说明零初始化。

所以“数据长度为零”不推出“这个范围是普通启动必写的全局区”。与全部现有观测相容的反例是：固件已执行若干指令，随后在非 PROT 数据/shared 访问或其他步骤停住，尚未访问 PROT。撤销 PROT 映射仍然可以得到 fault=0、版本哨兵不变。它与“没有完成初始取指”不会因此被区分。

即使另有证据确保该地址空间的缺页报告可靠，阴性至多限制对 PROT 的访问，仍不能推出“没有写任何全局变量”或“卡在取指阶段”。现有 witness 也尚未提供端到端取指/store 成功的正向基线。

### 2. 新引入的 fault 不能反推原先就卡在那里

撤销映射后若 fault 地址落在 PROT，能够支持“本次出现了对该 VA 的访问，并触发了可见故障”。需要同时解码 FAULTSTATUS 的故障种类和访问类型，才能区分 load/store 等情况；FAULTADDRESS 也不是指令 PC。

这仍不能证明 baseline 原先在相同访问上停住：baseline 该访问可能成功、之后才停；新 fault 则是干预新制造的停止点。交接第 115 行直接写“固件卡在写 .bss”，超出了该观测能支持的范围。

同理，仅版本字偏离哨兵也不等于启动完成，应结合有效版本、JOB global IRQ 和握手结果。`out/round-7.md:118` 已记录过这个判据边界。

## 对交接 §2.4 三条盲区的回答

1. **“少三个叶影响取指 walk”：机制需要纠正。** 三节共 `(0x03040000-0x03000000)/0x1000 = 64` 个 4K 叶。按驱动 `pt_map()` 的四级索引，代码 `0x01000000` 的起始索引为 `(0,0,8,0)`，PROT `0x03000000` 为 `(0,0,24,0)`。单独使后者的叶无效，不会在结构上使前者的有效叶失效。若取指地址出现新 fault，应检查原始故障类型、页表和其他变化，不能直接归因“少三叶”。整个分配块被跳过确实可能改变其他物理布局，这是另一个需要控制的因素。
2. **“witness=0 同时改变第二个变量”：不成立。** `out/round-8-support/trial-692-build.json:3` 已验证 `mali_witness=0`；`out/round-17-support/trial-692-analysis.json:108` 为 `witness_enabled: false`。693 若延续此值，行为开关变化只有 skipprot。无需补跑 skipprot+witness=1；那条路径不执行正常固件，也不访问 PROT，不能补足当前判据缺陷。
3. **“coverage 可能打印 HOLES”：按交接补丁，反而可能继续报告全部映射。** 驱动 `:1066–1207` 在待跳过的整个块内建立 section 并递增 `gSectCount`；coverage 在 `:1273` 仅遍历 `si < gSectCount`。被跳过的三个 PROT 条目根本不会被 coverage 统计。因此 `:1309` 的 `every section fully mapped` 不能验证 skipprot 是否精确生效。

上述驱动行号均对应 `/home/lizi/IOS/hakios-mtk/mtk/mt6895/drivers/gpu/hakios.mali610.c`。
